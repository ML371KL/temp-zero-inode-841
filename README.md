# Dual Assets BTC/USDT — радар

Панель реального времени по инструменту Bybit Dual Assets для пары BTC/USDT.
Показывает не заявленную ставку, а ту, которую вы действительно получите с
учётом реального срока блокировки денег, и оценивает риск конвертации двумя
независимыми способами.

Панель ничего не покупает и не хранит ключей. Все данные публичные.

## Что она считает

**Эффективный APR.** Проценты начисляются строго за номинальный срок продукта
(окно `subscribeEndAt → settlementTime`), а деньги заперты с момента покупки и
до зачисления через 20 минут после сеттлмента. Суточный продукт, купленный за
14 часов до закрытия окна подписки, держит капитал 1.6 суток ради одних суток
начисления — реальная ставка составляет 62% от заявленной.

**APR в непрерывном цикле.** Продукты выпускаются раз в сутки, поэтому катать
одну и ту же оферту подряд без простоя нельзя. Для «1d» полный оборот занимает
двое суток, для «8h» — сутки. Непрерывная стратегия на суточном продукте даёт
половину заявленной ставки.

**Вероятность конвертации** — двумя мерами сразу. Рыночная берётся из опционов
BTC на Bybit: они экспирируются в 08:00 UTC, ровно в момент сеттлмента Dual
Assets, поэтому для большинства сроков даты совпадают точно. Историческая —
эмпирическая частота по свечам за пять лет, приведённая к сегодняшней
волатильности и центрированная так, чтобы ожидаемая цена равнялась форварду. По
умолчанию используется худшая из двух. Мера меняет не одно число, а всю серию:
вероятность, глубина потери и ожидаемая доходность всегда считаются по одному
распределению.

**Глубина конвертации** рядом с её вероятностью. Частота отвечает «как часто»,
глубина — «сколько», и одной первой мало: на живых котировках при равной
вероятности около 7% ожидаемая потеря различается в пятнадцать раз — от 0.107%
капитала на суточном продукте до 1.570% на 236-дневном. Показываются три числа:
средняя потеря, потеря в самих случаях конвертации и потеря в худших 5% исходов.

**Премия сверх справедливой цены.** Buy Low — это проданный обеспеченный пут,
значит его можно оценить рынком опционов. Панель переводит оферту в
волатильность и сравнивает с рыночной: положительная разница означает, что
Bybit платит за риск больше биржи опционов.

**Перекосы лестницы.** На длинных сроках Bybit регулярно котирует страйк ближе
к рынку дешевле, чем страйк дальше: риск выше, а платят меньше. Такие оферты
помечаются знаком ⚠ с указанием, какой страйк их побивает; доля доходит до
трети от всех. Фронт Парето отбрасывает их автоматически.

**Два режима вместо одного «оптимума».** «Максимум доходности при минимуме
риска» — это два критерия, и ответ зависит от того, что именно вы измеряете.

- *Текущая подписка* — эффективный APR против вероятности конвертации этой
  покупки. Точный ответ для сравнения оферт одного срока.
- *Стратегия до даты* — ожидаемая стоимость капитала за горизонт против шанса
  закончить его в биткоине. Обе оси на одном горизонте и на одних исторических
  траекториях, поэтому сроки сравнимы между собой; после конвертации капитал
  моделируется дальше, а не обрывается.

Разница не косметическая: на одном и том же срезе рынка фронты этих двух
постановок пересекаются одной офертой из четырнадцати. Поэтому панель не
выбирает постановку за вас, а всегда пишет, в какой она сейчас. Проверить
расхождение на зафиксированном срезе можно самому:
`node scripts/frames.mjs --load docs/snapshot.json.gz`.

**Подбор Sell High после конвертации.** Вы вводите цену покупки BTC, панель
считает фактическую себестоимость (она ниже страйка, потому что конвертируется
и начисленный процент), порог безубытка (он ниже себестоимости, потому что за
срок начислится ещё процент) и подбирает оферты. Если безубыточный выход есть,
фронт строится по паре «прибыль к моменту выхода — шанс выйти за горизонт»:
прибыль считается с накоплением процента по всем циклам до продажи, а не за один.
Если рынок ушёл ниже себестоимости, срабатывание означало бы продажу в убыток, и
отбираются оферты с наибольшей ставкой при наименьшем риске такой продажи. Рядом
со «скоростью выхода» — которая по построению считает только желанную ветвь —
стоит полное матожидание обеих ветвей и база «просто держать биткоин»: без них
первое число читается как обещание.

Все формулы с выводом — в [docs/МАТЕМАТИКА.md](docs/МАТЕМАТИКА.md).
Результаты исторической проверки стратегии — в [docs/БЭКТЕСТ.md](docs/БЭКТЕСТ.md).

## Источники данных

| что | откуда | как часто |
| --- | --- | --- |
| продукты | `GET /v5/earn/advance/product?category=DualAssets&coin=BTC` | раз в 5 минут |
| лестницы страйков | WebSocket `earn.dualassets.offers` | в реальном времени |
| первичное заполнение | `GET /v5/earn/advance/product-extra-info` | при загрузке |
| спот | WebSocket `tickers.BTCUSDT` | в реальном времени |
| волатильность | `GET /v5/market/tickers?category=option&baseCoin=BTC` | раз в минуту |
| история цен | `GET /v5/market/kline` | раз в 30 минут |
| безрисковая ставка | `GET /v5/earn/product?category=FlexibleSaving&coin=USDT` | при загрузке |
| перцентили ставок | IndexedDB браузера, при наличии — `apr-stats.json` с ветки `data` | раз в минуту |

Аутентификация не требуется ни для одного из них, CORS у Bybit открыт, поэтому
статическая страница работает напрямую с биржей.

## Почему архив копится в браузере

Bybit блокирует диапазоны дата-центров через CloudFront. С раннеров GitHub
Actions **все** эндпоинты и **все** зеркала биржи (`api.bybit.com`,
`api.bytick.com`, `api.bybit.nl`) отдают 403 — это проверяется workflow
«Диагностика доступа к Bybit» (`scripts/probe.mjs`). Собирать историю ставок на
стороне репозитория поэтому нечем.

Панель работает из вашего браузера, где биржа доступна, и пишет снимки ставок в
IndexedDB раз в минуту, пока страница открыта. Перцентили считаются из них.
Ограничение честное и показано в подвале: выборка покрывает только те часы,
когда панель была открыта, а не непрерывный ряд.

Непрерывный архив на ветке `data` панель по-прежнему подхватит, если его кто-то
наполняет — своим self-hosted раннером или домашней машиной. Как это настроить,
описано в [docs/ПРОЕКТ.md](docs/ПРОЕКТ.md).

## Устройство

```
web/          страница целиком (публикуется на Pages как есть)
  quant.js      ядро формул, без DOM и сети
  surface.js    поверхность волатильности из опционов
  model.js      сборка строк и отбор вариантов
  feeds.js      REST и WebSocket Bybit
  charts.js     графики на голом SVG
  app.js        состояние и отрисовка
scripts/
  selftest.mjs  117 проверок: тождества, пример из документации, живые инварианты
  audit.mjs     150 проверок конвейера: Монте-Карло против аналитики, полный перебор
  frames.mjs    сравнение двух постановок задачи на одном срезе рынка
  record.mjs    снимок котировок в архив и пересборка перцентилей
  backtest.mjs  прогон стратегии по исторической цене BTC
docs/         математика, результаты бэктеста, эксплуатация, срез рынка
```

Ветка `data` хранит сжатый архив снимков (`history/ГГГГ-ММ-ДД.ndjson.gz`,
глубина 45 суток) и сводку перцентилей `apr-stats.json`, которую страница
тянет напрямую с raw.githubusercontent.com.

## Локальный запуск

```bash
node scripts/selftest.mjs
```

```bash
node scripts/audit.mjs
```

Первое — формулы сами по себе, второе — весь конвейер на живых котировках, где
аналитика сверяется с Монте-Карло, а отбор с полным перебором.

```bash
node scripts/frames.mjs --load docs/snapshot.json.gz
```

Третье считает по зафиксированному срезу рынка (он лежит в репозитории, 113 КБ)
все три постановки задачи рядом и печатает, насколько их ответы расходятся. Это
воспроизводится кем угодно и без доступа к бирже — именно затем срез и хранится.
Обновить срез: `node scripts/frames.mjs --save docs/snapshot.json.gz`.

```bash
python -m http.server 8642 --directory web
```

Сборки нет: страница на голых модулях ES, открывается по адресу
`http://localhost:8642`.
