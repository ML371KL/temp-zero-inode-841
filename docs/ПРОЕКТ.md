# Эксплуатация

## Что где живёт

- **ветка `main`** — код. Пуш в `web/**` публикует страницу через
  `.github/workflows/pages.yml`. Публикации предшествует `scripts/selftest.mjs`:
  если инварианты расписания продуктов разойдутся с биржей, панель не выедет.
- **ветка `data`** — архив. Каждый запуск `record.yml` пересоздаёт её одним
  коммитом (форс-пуш), поэтому история объектов не накапливается и размер ветки
  равен текущему дереву: около 5 МБ на 30 суток наблюдений.

Страница читает `apr-stats.json` прямо с `raw.githubusercontent.com`, поэтому
обновление перцентилей не требует пересборки Pages.

## Расписание записи

`record.yml` стоит на cron каждые 15 минут. Планировщик GitHub ненадёжен:
задержки в десятки минут и пропуски запусков — обычное дело, особенно на
загруженных часах. Если плотность наблюдений важна, продублируйте запуск
внешним планировщиком (например, cron-job.org), дёргающим

```
POST /repos/ML371KL/temp-zero-inode-841/actions/workflows/record.yml/dispatches
```

с телом `{"ref":"main"}` и токеном с правом `Actions: write`. Тот же приём уже
используется в соседних панелях.

## Проверки

```bash
node scripts/selftest.mjs
```

75 проверок: аналитические тождества Блэка-76, воспроизведение примера выплаты
из документации Bybit, поведение фронта Парето, разбор опционных символов и
живые инварианты — совпадение метки срока с окном начисления, одинаковая
задержка выдачи, длина цикла суточного и восьмичасового продуктов.

Флаг `--offline` пропускает обращения к бирже (57 проверок).

## Бэктест

```bash
node scripts/backtest.mjs --years 5 --durations 1d,6d,27d
```

Тянет часовые свечи (до 60 запросов, около минуты) и прогоняет «колесо» по
истории. Результаты и их разбор — в [БЭКТЕСТ.md](БЭКТЕСТ.md).

## Ловушки, на которые уже наступали

- **Отрисовка через `requestAnimationFrame`** не работает в фоновой вкладке:
  кадры не компонуются, и панель замирает. Используется `setTimeout`.
- **Выбор исторического ряда по числу окон** обманчив. Перекрывающиеся окна
  дают тысячи наблюдений внутри трёхмесячного ряда, но это порядка десятка
  независимых точек. Ряд выбирается по глубине истории, а число независимых
  окон показано в подсказке.
- **Экстраполяция лестницы ставок** за пределы котируемых страйков создаёт
  фантомные «безрисковые» уровни: до них цена не доходит, потому что их не
  существует. В бэктесте экстраполяция запрещена.
- **Знак риска в блоке Sell High переворачивается.** Пока выход безубыточен,
  срабатывание страйка — благо. Как только рынок ушёл ниже себестоимости,
  срабатывание означает продажу в убыток, и отбор должен минимизировать его
  вероятность, а не максимизировать ставку.
