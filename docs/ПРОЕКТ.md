# Эксплуатация

## Что где живёт

- **ветка `main`** — код. Пуш в `web/**` публикует страницу через
  `.github/workflows/pages.yml`. Публикации предшествует `scripts/selftest.mjs`:
  если инварианты расписания продуктов разойдутся с биржей, панель не выедет.
- **ветка `data`** — архив. Каждый запуск `record.yml` пересоздаёт её одним
  коммитом (форс-пуш), поэтому история объектов не накапливается и размер ветки
  равен текущему дереву: около 5 МБ на 30 суток наблюдений.

Страница читает `apr-stats.json` прямо с `raw.githubusercontent.com`, поэтому
обновление перцентилей не требует пересборки Pages.

## Архив ставок: почему не в Actions

Bybit фильтрует диапазоны дата-центров через CloudFront. С раннеров GitHub
**все** эндпоинты и **все** зеркала биржи отдают 403:

```
403 /v5/earn/advance/product  — The Amazon CloudFront distribution is configured to block access…
403 /v5/market/tickers        — то же самое
403 api.bytick.com, api.bybit.nl — то же самое
```

Проверяется в любой момент запуском workflow «Диагностика доступа к Bybit»
(`scripts/probe.mjs`). Поэтому у `record.yml` нет расписания: оно давало бы
только поток красных прогонов и уведомлений.

Рабочая схема — архив в браузере (`web/archive.js`): снимок раз в минуту в
IndexedDB, глубина 60 суток, перцентили считаются на месте. Формат сводки тот
же, что публикует `record.mjs`, поэтому страница не различает источники и
предпочитает внешний, если он есть.

### Как всё-таки собрать непрерывный ряд

Нужна машина в незаблокированной сети — например, ваш домашний компьютер.

```bash
git clone --branch data https://github.com/ML371KL/temp-zero-inode-841.git data-branch
node scripts/record.mjs --out data-branch
```

Дальше запуск раз в 15 минут планировщиком задач Windows и пуш ветки `data`.
Страница подхватит `apr-stats.json` с `raw.githubusercontent.com` без
пересборки Pages. Второй вариант — self-hosted раннер на той же машине: тогда
`record.yml` заработает как есть, достаточно вернуть ему расписание.

## Проверки

```bash
node scripts/selftest.mjs
```

Аналитические тождества Блэка-76 и обратной функции распределения,
воспроизведение примера выплаты из документации Bybit, профиль глубины потери,
мартингальное центрирование исторической меры, траекторный слой и накопление
процента по циклам, поведение фронта Парето и отбора карточек, разбор опционных
символов и живые инварианты — совпадение метки срока с окном начисления,
одинаковая задержка выдачи, длина цикла суточного и восьмичасового продуктов.

Флаг `--offline` пропускает обращения к бирже (141 проверка). Отдельно есть
`node scripts/audit.mjs` — 166 проверок всего конвейера на живых котировках:
вероятности и глубина сверяются с Монте-Карло, оба фронта и оба режима — с
полным перебором, попутевые траекторные ряды — с отсортированными.

```bash
node scripts/frames.mjs --load docs/snapshot.json.gz
```

Считает три постановки задачи рядом на зафиксированном срезе рынка и печатает,
насколько расходятся их ответы. Работает без сети, поэтому воспроизводится кем
угодно; срез обновляется флагом `--save`.

## Бэктест

```bash
node scripts/backtest.mjs --years 5 --durations 1d,6d,27d
```

Тянет часовые свечи (до 60 запросов, около минуты) и прогоняет «колесо» по
истории. Результаты и их разбор — в [БЭКТЕСТ.md](БЭКТЕСТ.md).

## Если скрипты не достукиваются до биржи

Node не использует системный прокси по умолчанию, поэтому в окружении, где
трафик идёт через `HTTPS_PROXY`, `fetch` из скриптов упирается в
`UND_ERR_CONNECT_TIMEOUT`, хотя `curl` в той же оболочке работает. Признак
однозначный: `curl -w "%{remote_ip}"` показывает `127.0.0.1`.

Скрипты запускаются с флагом `--use-env-proxy`, который включает уважение к
переменным окружения. Переменная `NODE_USE_ENV_PROXY=1` делает то же самое, но
только если выставлена до запуска процесса: изнутри скрипта она уже не
действует, undici читает её при инициализации.

## Ловушки, на которые уже наступали

- **Отрисовка через `requestAnimationFrame`** не работает в фоновой вкладке:
  кадры не компонуются, и панель замирает. Используется `setTimeout`.
- **Выбор исторического ряда по числу окон** обманчив. Перекрывающиеся окна
  дают тысячи наблюдений внутри трёхмесячного ряда, но это порядка десятка
  независимых точек. Ряд выбирается по глубине истории, а число независимых
  окон показано в подсказке.
- **Экстраполяция лестницы ставок** за пределы котируемых страйков создаёт
  фантомные «безрисковые» уровни: до них цена не доходит, потому что их не
  существует. В бэктесте экстраполяция запрещена.
- **Знак риска в блоке Sell High переворачивается.** Пока выход безубыточен,
  срабатывание страйка — благо. Как только рынок ушёл ниже себестоимости,
  срабатывание означает продажу в убыток, и отбор должен минимизировать его
  вероятность, а не максимизировать ставку.
