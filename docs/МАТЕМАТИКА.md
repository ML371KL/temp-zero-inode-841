# Математика Dual Assets BTC/USDT

Документ описывает все формулы панели. Код в `web/quant.js` — исполняемая
версия этого текста; при расхождении верен код, а текст надо править.

## 1. Что такое Dual Assets

**Buy Low.** Вкладывается сумма `A` USDT со страйком `K` ниже рынка. К моменту
сеттлмента начислен процент, итого `A(1+i)`. Дальше:

- если цена сеттлмента `S_T > K` — возвращают `A(1+i)` USDT;
- если `S_T ≤ K` — возвращают `A(1+i)/K` биткоинов.

Выплата в пересчёте на USDT равна `A(1+i)·min(1, S_T/K)`. Это в точности
**проданный обеспеченный пут** со страйком `K` в количестве `A(1+i)/K` штук
плюс денежная позиция. Ключевая деталь: конвертируется не только тело, но и
начисленный процент.

**Sell High.** Вкладывается `Q` BTC со страйком `K` выше рынка, к сеттлменту
`Q(1+i)` BTC.

- если `S_T < K` — остаются `Q(1+i)` BTC;
- если `S_T ≥ K` — возвращают `Q(1+i)·K` USDT.

Выплата в USDT равна `Q(1+i)·min(S_T, K)` — **проданный колл**.

## 2. Начисление процентов и реальный срок блокировки

Это самое важное место, и именно здесь заявленный APR вводит в заблуждение.

Продукт отдаёт четыре момента времени:

| поле | смысл |
| --- | --- |
| `subscribeStartAt` | открытие окна подписки |
| `subscribeEndAt` | закрытие окна подписки |
| `settlementTime` | момент сеттлмента (08:00 UTC) |
| `expectReceiveAt` | зачисление средств, сеттлмент + 20 минут |

Проценты начисляются **строго в окне `[subscribeEndAt, settlementTime]`**, и
это окно в точности равно номинальному сроку продукта:

```
D = (settlementTime − subscribeEndAt) / сутки        // 8h, 1d, 3d, …
i = APY · D / 365                                    // простые, без капитализации
выплата = A · (1 + i)                                // Bybit усекает до точности монеты
```

Проверено на примере из документации Bybit (`Get Position Info`): 20 USDT,
APY 9.027, срок 3d → `20 · (1 + 9.027·3/365) = 21.48389…`, биржа показывает
`21.4838`. Совпадает при усечении, а не округлении.

Деньги при этом заперты с момента покупки `T₀` и до зачисления:

```
L = (expectReceiveAt − T₀) / сутки                   // реальная блокировка
мёртвое время = L − D
```

Отсюда главная метрика панели:

```
эффективный APR = APY · D / L
```

Пример: суточный продукт, купленный за 14 часов до закрытия окна, держит деньги
1.6 суток ради одних суток начисления — множитель 0.62. Тот же продукт,
купленный за минуту до закрытия окна, даёт множитель 0.99. Заявленная ставка в
обоих случаях одинакова.

## 3. Доходность непрерывной стратегии

Продукты каждого срока выпускаются раз в сутки. Значит, деньги, вернувшиеся
после сеттлмента, не могут сразу войти в следующую такую же оферту: надо ждать
закрытия очередного окна подписки. Длина полного оборота:

```
следующее окно = subscribeEndAt + k·сутки,  k = ⌈(expectReceiveAt − subscribeEndAt)/сутки⌉
цикл = (следующее окно − settlementTime)/сутки + D
APR в цикле = APY · D / цикл
```

Для суточного продукта цикл равен ровно двум суткам, для восьмичасового — ровно
суткам. То есть непрерывная езда на «1d» даёт половину заявленной ставки, а на
«8h» — треть. На «27d» цикл 28 суток, потери всего 3.6%. Проверяется на живых
данных в `scripts/selftest.mjs`.

Обе метрики нужны и означают разное: **эффективный APR** отвечает на вопрос
«сколько даст эта конкретная покупка сейчас», **APR в цикле** — «сколько это
даст в год, если делать так постоянно».

## 4. Вероятность конвертации

Цена сеттлмента — средняя спот-цена Bybit за 30 минут до 08:00 UTC. Среднее по
хвосту траектории менее изменчиво, чем точечная цена: для среднего
геометрического броуновского движения на отрезке `[T−Δ, T]`

```
Var(ln A) ≈ σ²·(T − 2Δ/3)      →     T_эфф = T − 2Δ/3
```

На восьмичасовом продукте поправка срезает около 4% срока, на длинных
незаметна.

### Рыночная оценка

Опционы BTC на Bybit экспирируются в 08:00 UTC — в тот же момент, что и
сеттлмент Dual Assets. Для сроков 1d, 6d, 13d, 27d, 55d, 146d, 237d даты
совпадают с котируемыми экспирациями точно; для 3d и 5d интерполируем.

Поверхность строится по `markIv`: улыбка линейна по `ln(K/F)`, между
экспирациями интерполируется полная дисперсия `σ²T` (так поверхность остаётся
свободной от календарного арбитража). Форвард берётся из `underlyingPrice`
соответствующей экспирации.

```
d₂ = [ln(F/K) − σ²T_эфф/2] / (σ√T_эфф)
P(конвертации Buy Low) = N(−d₂)
P(продажи Sell High)   = N(d₂)
```

### Историческая оценка

Эмпирическая частота: доля окон длины τ в истории цен BTC, где доходность
оказалась ниже `ln(K/S₀)`.

Здесь легко обмануться. Перекрывающиеся окна создают иллюзию большой выборки:
тысяча часовых окон по шесть дней внутри трёхмесячного ряда — это порядка
десятка независимых наблюдений, то есть замер тренда последних месяцев, а не
распределение. Поэтому ряд выбирается по максимальной глубине истории при
достаточном разрешении горизонта, а в подсказке к каждой строке показано число
**независимых** окон. Оценка включает исторический дрейф цены и этим отличается
от рыночной, которая дрейфа не содержит по построению.

### Приведение истории к сегодняшнему рынку

Сырая частота описывает мир, из которого взята выборка. Замер по пяти годам
BTC: реализованная волатильность 52.5% годовых, за последние 30 дней 29.7%, а
рынок опционов оценивает ближайшие дни в 17–25%. Подставлять в решение о
завтрашней оферте распределение с волатильностью 52% — значит мерить не
сегодняшний риск, а средний за пять лет.

Поэтому выборка приводится к текущему рынку:

```
r' = (r − среднее выборки) · σ_рынка·√T_эфф / σ_выборки + ln(F/S)
r'' = r' + ln( (F/S) / среднее(e^{r'}) )        // мартингальная поправка
```

Убирается собственный дрейф выборки (направление прошлого — плохой прогноз),
масштаб ставится по сегодняшней волатильности, сносом берётся сегодняшний
форвард. Остаётся то, ради чего историю и берут: форма распределения, то есть
толстые хвосты и асимметрия, которых нет у логнормального приближения.

**Вторая строка обязательна, и её отсутствие было настоящей ошибкой.** Первая
ставит в форвард среднее логарифма, то есть примерно медиану цены. Но из-за
выпуклости экспоненты `E[e^{r'}] > e^{E[r']}`, и среднее самой цены уезжает выше
форварда тем сильнее, чем длиннее срок и толще хвосты. Замер на живых данных:
на 236-дневном продукте `E[S_T]/S` получалось 1.083 при форварде 1.027 — то есть
в меру риска молча зашивался прогноз роста биткоина на 8.6% годовых, ровно тот
самый «направление прошлого», который абзацем выше объявлен плохим прогнозом.
Поправка это убирает: после неё `E[S_T] = F` точно, а форма распределения не
меняется, потому что сдвиг общий для всей выборки.

На текущем рынке нормировка снижает вероятность у подавляющего большинства
строк — просто потому, что сегодня тише, чем было в среднем за пять лет.

### Серия целиком, а не одна величина

Мера — это не число, а распределение, и все производные от него величины обязаны
считаться по одному и тому же распределению. Поэтому вероятность, ожидаемая
потеря и ожидаемая чистая доходность живут двумя параллельными сериями:

| серия | вероятность | глубина потери | ожидаемая доходность |
| --- | --- | --- | --- |
| сырая | `pHist` | `lossHist` | `expNetApr` |
| нормированная | `pHistScaled` | `lossHistScaled` | `expNetAprScaled` |

Раньше вероятность бралась из нормированного мира, а ожидаемая потеря — из
сырого, и одна карточка описывала два разных рынка сразу. На живых данных это
меняло не оттенок, а ответ: якорь «лучшее матожидание» переезжал с 145-дневного
страйка на −44% от рынка на 12-дневный у самой цены.

## 4а. Глубина конвертации

Вероятность отвечает только на вопрос «как часто» и ничего не знает о том,
сколько теряется. Это не придирка: на живых котировках при одной и той же
вероятности около 7% ожидаемая потеря различается **в пятнадцать раз**.

```
безусловная  = E[(K − S_T)⁺]/K            // доля вложенного капитала
условная     = безусловная / P(конверсии) // сколько теряется, когда сработало
стресс       = (K − S_{5%})⁺/K            // потеря в худших 5% исходов
```

Под мерой Q все три берутся из той же цены опциона: безусловная — это `Put/K`,
квантиль цены `S_q = F·exp(σ√T_эфф·N⁻¹(q) − σ²T_эфф/2)`. По исторической мере —
прямым счётом по выборке. В осторожном режиме берётся худшее из двух по каждому
из трёх чисел, с тем же порогом по весу выборки, что и у вероятности.

Пример с живых данных при вероятности около 7%:

| срок | страйк | безусловная | условная | стресс 5% |
| --- | --- | --- | --- | --- |
| 1d | −2.6% | 0.107% | 1.42% | 0.57% |
| 12d | −11.4% | 0.320% | 5.17% | 1.35% |
| 54d | −20.1% | 0.929% | 8.10% | 7.62% |
| 236d | −52.1% | 1.570% | 18.27% | 12.41% |

Ползунок «порог вероятности» ограничивает частоту события, но не деньги под
риском. Поэтому глубина стоит в таблице рядом с вероятностью, а не отдельно.

Историческая оценка любого вида учитывается в осторожном режиме только при
тридцати и более независимых окнах. Пять лет вмещают восемь непересекающихся
237-дневных окон, и оценка вероятности по восьми наблюдениям имеет
стандартную ошибку около десяти процентных пунктов.

Режим «худшая из двух» берёт максимум рыночной и нормированной исторической.
Расхождение между ними само по себе информативно: рынок опционов оценивает
будущее, история — форму прошлого.

## 5. Премия сверх справедливой цены

Buy Low — это проданный пут, значит его можно оценить рынком опционов.
Справедливая (под мерой Q) стоимость вложенного доллара:

```
V = (1 + i)·(1 − Put(F, K, σ, T_эфф)/K)·DF
премия, годовых = (V − 1)·365/L
```

Для Sell High через колл: `V = (1+i)(F − Call)/F·DF_BTC`.

**Дисконт у направлений разный, и это не мелочь.** Buy Low вложен в USDT и
возвращается в USDT: ожидание выплаты надо привести к сегодняшнему дню по
долларовой ставке, причём на срок реального удержания денег `L`, потому что
простой между сеттлментом и зачислением тоже стоит денег. Sell High вложен в
биткоин, а его выплата нормирована на форвард — и деление на `F` **уже содержит**
долларовый дисконт: при нулевой ставке заимствования монеты `DF_T·F = S`, то есть
`(F − Call)/F` и есть стоимость в долях сегодняшнего биткоина. Умножать это ещё
раз на долларовую ставку значит применить её дважды. Правильная поправка здесь —
ставка, под которую можно было бы отдать сам биткоин; она берётся с той же ручки
биржи, что и долларовая, и сегодня составляет 0.1% против 1.56% у USDT.

Обратная задача даёт самое наглядное число — **волатильность оферты**:
```
σ_оферты решает   Put(F, K, σ, T_эфф) = K·i/(1+i)
```
Если `σ_оферты > σ_рынка`, Bybit платит за риск больше рынка опционов; если
меньше — вы продаёте волатильность дешевле, чем это делают на бирже опционов.
На практике по BTC чаще наблюдается второе, и панель это честно показывает.

## 6. Ожидаемая чистая доходность

По историческому распределению считается ожидаемая потеря на конвертации:

```
shortfall = E[(K − S_T)⁺] / K
ожидаемый чистый APR = ((1+i)(1 − shortfall) − 1) · 365 / L
```

Это оценка «в среднем», а не гарантия. Для страйков у самой цены она обычно
глубоко отрицательна: премия не покрывает ожидаемого убытка от покупки
падающего актива.

## 7. Отбор оптимальных вариантов: две постановки, а не одна

Задача «максимум APR при минимуме риска» не имеет единственного решения — это
два критерия сразу, и честный ответ на них — **фронт Парето**. Но прежде чем
строить фронт, надо ответить на вопрос, который панель раньше обходила молчанием:
*фронт чего именно*.

### В чём была проблема

Пара `(эффективный APR, вероятность конвертации за сделку)` кажется естественной,
но её оси делают взаимоисключающие предположения об одном и том же решении.

`aprEff = i·365/L` осмыслен как доходность только если капитал переразмещается
после разблокировки: восьмичасовая сделка на 0.2% не даёт 123% годовых, если не
повторить её шестьсот раз. То есть ось доходности неявно считает, что вы будете
крутить оферту. `pConv` при этом — вероятность ровно одной сделки, то есть ось
риска считает, что сделка одна.

Последствие не косметическое. При фиксированной вероятности справедливая ставка
за сделку растёт примерно как `σ√T`, значит `aprEff ≈ σ/√T` — **убывает с
корнем из срока**. Короткий продукт при равном риске механически показывает
больший годовой APR не потому, что он выгоднее, а потому, что делится на меньшее
число. На живых данных фронт по этой паре не содержал ни одной оферты длиннее
12 дней ни при какой настройке меры.

Второе следствие видно прямо в таблице: у восьмичасовой оферты вероятность
конвертации за сделку 3.5%, а вероятность конвертироваться хотя бы раз за
90 дней — 86%. Первое число панель показывала, второго не было.

### Две постановки

**Текущая подписка.** `(aprEff ↑, pConv ↓)`, порог задаёт пользователь. Отвечает
на вопрос «какая из сегодняшних покупок даёт наибольший годовой темп при
заданном шансе конвертации именно на её сеттлменте». Для сравнения оферт **одного
срока** это точный ответ: там `L` одинаков, поэтому `aprEff ∝ i`, и обе оси
относятся к одному и тому же событию. Между сроками — читать с оговоркой,
которая теперь написана прямо над блоком.

**Стратегия до даты.** `(ожидаемая годовая стоимость ↑, шанс закончить в BTC ↓)`,
обе оси на одном горизонте H и на одних траекториях. Описана в разделе 7а.

Эти два ответа расходятся почти полностью. Замер на зафиксированном срезе
(`docs/snapshot.json.gz`, воспроизводится через `node scripts/frames.mjs --load`):
фронт подписки — 8h/1d/3d/5d/12d/26d, фронт стратегии — 1d/3d/5d/12d/26d/54d,
общих оферт одна из четырнадцати. Поэтому панель не выбирает постановку за
пользователя, а показывает переключатель и всегда пишет, в каком она режиме.

### Блок карточек

Внутри порога берётся фронт, но показываются не первые шесть строк по
доходности. Шесть подряд с верхнего края — это шесть самых рискованных точек
разрешённого диапазона: при подъёме порога с 15% до 30% из блока пропадали все
осторожные варианты, включая лучшую по цене оферту книги. Поэтому блок содержит
максимум доходности, максимум премии к рынку опционов и равномерный срез фронта
между ними; каждая карточка подписана, почему она здесь.

## 7а. Стратегия до выбранной даты

Капитал катает одну и ту же оферту, пока цена не уйдёт ниже страйка; после
конвертации биткоин держится до конца горизонта. По каждой исторической
траектории:

```
k = первый цикл, где цена на сеттлменте оказалась ниже страйка
конвертации не было → (1+i)^n · (1 + r_f·хвост/365)   USDT
конвертация на k    → (1+i)^k · S_H / K                биткоинов по цене конца H
стоимость = среднее по траекториям,  годовая = стоимость^(365/H) − 1
риск      = доля траекторий, где конвертация случилась
```

Контрольные точки — концы циклов, `n = ⌊H/цикл⌋`, а хвост горизонта, не покрытый
целыми циклами, считается лежащим в USDT под безрисковую ставку. Цена конца
берётся **на H**, а не на последнем цикле: иначе 236-дневный продукт при
горизонте 365 оценивался бы по 237-му дню, то есть на окне другой длины.

Политика после конвертации — `hold` из бэктеста: обратная нога Sell High
консервативно считается нулевой. Основание в `docs/БЭКТЕСТ.md`: безубыточного
страйка нет от 69% до 91% времени, проведённого в биткоине, а когда он есть, то
добавляет 3–9% годовых в монетах. Модель занижает ценность конвертации, и это
осознанный запас, а не пропуск.

Что модель принимает на веру: ставка и лестница страйков неизменны на весь
горизонт, а распределение цены историческое — со всем реализованным дрейфом BTC.
Поэтому рядом всегда стоят две базы сравнения на тех же траекториях: удержание
USDT под безрисковую ставку и удержание биткоина. У последнего показываются и
среднее, и медиана, и расхождение между ними огромно — на пятилетней выборке
среднее годовое удержание BTC даёт около +30%, медианное около +4.5%. Среднее
задаёт правый хвост, и планировать по нему нельзя; медиана рядом стоит именно
для того, чтобы это было видно.

## 8. Перекосы лестницы

По смыслу инструмента ставка обязана расти по мере приближения страйка к рынку:
ближе страйк — выше шанс конвертации — выше плата за риск. На длинных сроках
Bybit это правило регулярно нарушает. Пример из живых котировок:

```
146d: страйк 59 000 → 14.35%,   страйк 59 500 → 10.08%
237d: страйк 60 000 → 13.91%,   страйк 61 000 →  1.47%
27d:  страйк 58 000 → 15.54%,   страйк 58 500 → 14.38%
```

Котировки при этом одновременные и свежие, так что дело не в устаревании.
Оферта, у которой в той же лестнице есть страйк дальше от рынка с не меньшей
ставкой, бессмысленна: тот же продукт, тот же сеттлмент, но и риск выше, и
платят меньше. Такие строки помечаются знаком ⚠, а в подсказке указано, какой
именно страйк их побивает. Доля таких оферт доходит до трети от всех.

Фронт Парето отбрасывает их автоматически — это одна из причин, по которой
выбирать стоит по фронту, а не по столбцу «APR».

## 9. После конвертации

Себестоимость полученного BTC ниже страйка, потому что конвертируется и
процент:

```
себестоимость = K / (1 + i)
```

Порог безубытка для выхода: продаётся `Q(1+i)` BTC по цене `K_s`, выручка
должна покрыть `Q·себестоимость`, отсюда

```
K_s ≥ себестоимость / (1 + i_s)
```

То есть начисляемый процент позволяет выходить и **ниже** себестоимости.

Знак риска в этом блоке зависит от ситуации:

- **безубыточные оферты есть** — срабатывание страйка желанно, и фронт строится
  по паре «прибыль к себестоимости — вероятность продажи». Брать здесь
  эффективный APR нельзя: вдоль лестницы Sell High ставка и вероятность
  срабатывания движутся в одну сторону, поэтому пара из них почти не даёт фронта
  (на живых данных две оферты из 186 безубыточных) и всегда тянет к нижнему
  страйку, то есть к минимальной выручке. Прибыль и вероятность, наоборот,
  тянут в разные стороны: та же выборка даёт 16 недоминируемых оферт с выручкой
  от долей процента до 36%;
- **безубыточных нет** (рынок ушёл ниже себестоимости) — срабатывание означает
  принудительную продажу в убыток, поэтому максимизируем ставку при
  **минимальной** вероятности срабатывания.

### Горизонт выхода

Вероятность продажи за один цикл несравнима между продуктами разного срока:
47% за 55 дней и 41% за 237 дней — величины разной размерности, и фронт,
построенный по такой оси, механически вытаскивает наверх самые длинные
продукты. На живых данных фронт по паре «прибыль — вероятность за цикл»
состоял почти целиком из 145- и 237-дневных оферт, а лучшая по прибыли
(+36% при страйке 90 000) имеет шанс вывести вас в USDT за 90 дней, равный нулю:
она за это время просто не рассчитывается.

Поэтому ось риска приведена к общему горизонту H: **шанс выйти за H дней, если
крутить одну и ту же оферту**. Контрольные точки — концы циклов внутри
горизонта, число полных циклов n = ⌊H/цикл⌋.

Считать это как `1 − (1 − p)ⁿ` нельзя. Соседние циклы сильно зависимы: если
рынок ушёл вниз и там остался, промахи идут подряд. Замер на пяти годах BTC
показал, что формула независимости завышает шанс выхода на **10–22 процентных
пункта**. Поэтому частота берётся прямо по историческим траекториям: для
каждого старта запоминается максимум отношения цены к стартовой по всем
контрольным точкам, а вероятность для страйка — доля траекторий, где этот
максимум достиг цели.

Смена горизонта заметно меняет состав фронта: на 90 днях в нём только продукты
до 55 дней, на 180 появляются 145-дневные, на 365 — 237-дневные.

Оферты с нулевым шансом выйти за горизонт исключаются до построения фронта.
Формально самая прибыльная из них недоминируема — по прибыли её никто не
превосходит, — и она садилась на край фронта с обещанием +36% при шансе
получить их, равном нулю. Недоминируемость здесь вырождена.

### Прибыль считается к моменту выхода, а не за один цикл

Если продажа состоялась на цикле `k`, процент в биткоине начислялся `k` раз, а не
один: на руках `Q(1+i)^k` монет. Поэтому ось прибыли на фронте — ожидание
`(1+i)^k·K/basis − 1` по тем траекториям, где выход состоялся, а прибыль за один
цикл остаётся отдельной колонкой как ответ на вопрос «что будет, если сработает
на ближайшем сеттлменте». Разница доходит до трёх раз и бьёт **неравномерно**:
сильнее всего по коротким циклам, где накопление успевает поработать, то есть
ровно по тем офертам, которые старая формула и без того недооценивала.

### Ожидание выхода и скорость

Прибыль реализуется не сразу и не наверняка, поэтому две оферты с одинаковой
прибылью и одинаковым шансом выйти всё равно не равноценны: одна освобождает
капитал через неделю, другая через полгода. Из тех же траекторий берётся

```
ожидание = E[min(T, n)] · цикл,   E[min(T, n)] = Σ_{k=0..n−1} P(T > k)
```

где `P(T > k)` — доля траекторий, у которых нарастающий максимум за k циклов не
достал до страйка. Отсюда сводный показатель:

```
скорость безубыточного выхода = прибыль к выходу · шанс выйти · 365 / H
```

**Знаменатель здесь именно H, а не длина цикла и не ожидание.** У 54-дневного
продукта при горизонте 90 укладывается ровно один цикл, и деление на 55 дней
вместо 90 завышало его годовые в полтора раза против пятидневного — то есть
приведение к общему горизонту, ради которого всё и делалось, ломалось в самом
последнем действии.

### Это не ожидаемая доходность

Скорость выхода считает только ту ветвь, ради которой всё затевается, и ветвь
«выход не состоялся» в ней стоит ноль. Поэтому она всегда положительна и всегда
выглядит привлекательно. Рядом считается **полное матожидание обеих ветвей**:

```
выход на цикле k → (1+i)^k·K/basis, дальше USDT под безрисковую до конца H
выхода не было  → (1+i)^n монет по цене конца горизонта
```

и его медиана. На живых данных при себестоимости 66 283 и споте 62 600 лучшая по
скорости оферта показывает +13% годовых по ветви выхода и −13% по полному
матожиданию, тогда как простое удержание биткоина те же 90 дней даёт +4.7% в
среднем. Разница — цена обрезанного верха, и она же плата за возможность выйти.
Обе величины нужны и означают разное: первая ранжирует оферты внутри задачи
«как быстрее выйти в безубыток», вторая отвечает на вопрос, стоило ли вообще
продавать колл вместо того, чтобы просто ждать. Ранжирование по ним совпадает
почти полностью, а численно они расходятся на десятки процентных пунктов —
именно поэтому первая переименована из «ожидаемой доходности» в «скорость».

Для второго случая считается, за сколько циклов процент в BTC закроет разрыв,
если цена не двинется:

```
циклов = ⌈ ln(себестоимость / цена) / ln(1 + i_s) ⌉
```

## 10. Что панель не моделирует

- Комиссий у Dual Assets нет, но за подписку деньги должны лежать в Funding или
  Unified — перевод между счетами тут не учитывается.
- Лимит `maxInvestmentAmount` показывается колонкой и подсвечивается красным,
  когда введённая сумма его превышает, но в отбор не заложен: оферта с малым
  лимитом остаётся на фронте.
- Ёмкость продукта (`remainingAmountQuote`) и минимальная сумма подписки
  (`minPurchaseQuoteAmount`) не читаются. Сегодня они не жмут — ёмкость 3–4 млн
  USDT, минимум 20 USDT, — но это допущение, а не проверка.
- Доступность VIP-продуктов не проверяется: галочка просто включает их в выборку.
- Ставки котируются 8–20 секунд. Панель показывает живую котировку и время до её
  истечения отдельной колонкой, но между расчётом и отправкой ордера ставка может
  измениться, и биржа подтвердит сделку по своей.
- В режиме стратегии ставка и лестница страйков приняты неизменными на весь
  горизонт, а обратная нога Sell High после конвертации считается нулевой.
- Историческая мера в траекторных расчётах не нормируется к сегодняшней
  волатильности: приведение, описанное в разделе 4, применимо к распределению
  доходности на горизонте, но не к последовательности цен вдоль траектории.
  Поэтому рядом с любым траекторным числом стоят базы сравнения на тех же
  траекториях — только их разность осмысленна, а не абсолютная величина.
